Keep the next feature easy: deepen the code, and fix the agent's environment.

Sources: codebase-design (+ DEEPENING.md), improve-codebase-architecture, retro, and their guides, commit 5beb35b.

Four principles

  1. Deletion test: if complexity vanishes, the module was a pass-through; if it reappears across callers, it earns its keep.
  2. The interface is the test surface. Wanting to test past it means the module is the wrong shape.
  3. One adapter = hypothetical seam; two = real.
  4. Depth belongs to the interface. Internal seams stay private.

Testing across the seam, by dependency

DependencyTest with
In-processMerge and test directly; no adapter
Local-substitutableA local stand-in (PGLite, in-memory FS)
Remote but ownedA port: HTTP adapter for production, in-memory adapter for tests
True externalAn injected port with a mock adapter

Replace, don't layer: once tests at the deepened interface exist, delete the old shallow unit tests.

/improve-codebase-architecture

  1. Scope: take your direction, or read git log for hot spots. Best prompt: point it at the next spec and ask "how can we make this change easy?"
  2. A subagent explores; each candidate must pass the deletion test.
  3. An HTML report in $TMPDIR, with badges Strong / Worth exploring / Speculative. It then stops and asks. It changes no code.
  4. Grill one candidate → decision → /to-spec → /to-tickets → /implement. Use one candidate per session.
  • All Speculative means it found nothing.
  • If it over-grills, say "don't grill me, just show the report."
  • A rejection with a lasting reason becomes an ADR.
  • Never drive a session with /codebase-design alone. It's a reference, not a process.
