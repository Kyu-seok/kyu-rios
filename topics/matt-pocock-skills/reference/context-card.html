Context Card

What to do with the context at a phase boundary.

Sources: ask-matt/PHASE-BOUNDARIES.md, handoff (guide), commit 5beb35b.

When

Decide only at a phase boundary, the point where you think "ok, we're done with that." Mid-phase there are two choices: continue, or split what's left into subagents. Never compact mid-phase.

The tree: first yes wins

  1. Continue: the next phase needs this one verbatim (a primary source), or there's smart zone left (~150k). Grilling → implement, and /to-spec → /to-tickets.
  2. /clear: everything here is disposable. It's the cheapest move, and it only works one way (you lose the why). Use it between tickets.
  3. /handoff: the work must travel to a new harness, a new directory, a colleague, or a mid-phase fork (the prototype detour).
  4. Subagent: the task can run AFK with no steering. Automated review is the standard case.
  5. /compact <what's next>: everything else. It's the default, not the first reach.

What each move keeps

MoveKeepsSource after
ContinueEverythingPrimary
/compactYour intentSecondary (lossy)
/handoffThe work's ability to moveSecondary (a file)
/clearNothing (the old session can still be resumed)None

/handoff checklist

  • Pass what the next session is for: /handoff QA the reset flow in Codex.
  • The file goes to $TMPDIR. Ask for the path, and copy it somewhere durable if the next session isn't soon.
  • It references specs, ADRs, issues and diffs by path or URL. It doesn't copy them. Secrets are redacted.
  • Read it before passing it on, and downgrade any claim nobody verified.
  • Start the new session by pointing it at the file. Don't paste the summary into a shell command.
  • If it's still true next month, it belongs in CLAUDE.md. Work in progress belongs in a handoff.
