1 · What makes one model differ from another

You'll mostly use models, not build them. Still, Huyen traces most differences between models to three decisions: training data, architecture and size, and post-training. Ch2 intro

  • Data. A model can't do what its data never showed it. With no Vietnamese in the training data, there's no English→Vietnamese translation. Quality can beat quantity: a 1.3B-parameter model trained on 7B tokens of high-quality code outperformed much larger models on coding benchmarks. Ch2 · Training Data
  • Architecture. Nearly every model you'll use is a transformer. You can skip its internals for now.
  • Size is measured in parameters: “Llama-13B” has 13 billion. Bigger usually means more capable within a model family, though newer small models often beat older big ones: Llama 3-8B beats Llama 2-70B on MMLU. Ch2 · Model Size

Napkin math you'll reuse Each parameter stored in 16 bits takes 2 bytes, so a 7B model needs at least 14 GB of GPU memory just to run inference. Ch2 · Model Size Chapter 7 builds on this arithmetic.

2 · From monster to assistant: the training pipeline

Why SFT is needed. A pre-trained model only completes text. Give it “How to make pizza” and “for a family of six?” is a perfectly valid completion. SFT trains it on high-quality demonstration data, (prompt, response) pairs, often written by highly educated labelers at up to 30 minutes per pair. Ch2 · Supervised Finetuning

Why preference finetuning is needed. Demonstrations teach the model how to converse but not which conversations to have. In RLHF, you first train a reward model that scores responses, then optimize the language model to earn high scores. The reward model learns from comparison data, (prompt, winning response, losing response), because people agree far more on “A beats B” than on a 1–10 score. DPO is a simpler alternative; Meta switched to it for Llama 3. Ch2 · Preference Finetuning, Reward model

Pre-training [is like] reading to acquire knowledge, while post-training is like learning how to use that knowledge.Huyen, Ch. 2, “Post-Training”

3 · Sampling: how the model picks each token

For every next token, the model outputs one logit (a raw score) per token in its vocabulary. Softmax turns the logits into probabilities. Then a token is sampled. Huyen calls sampling “perhaps one of the most underrated concepts in AI.” Ch2 · Sampling

4 · The probabilistic nature of AI

Anything with a non-zero probability can come out, “no matter how far-fetched or wrong.” Ch2 · The Probabilistic Nature of AI That causes two problems you'll fight for the rest of the book:

Inconsistency

The same input can give different outputs (Huyen got 3/5 and then 5/5 grading the same essay), and a slightly different input can give a very different output. Mitigations: cache answers; fix temperature, top-p, and top-k; fix the seed. Even then, identical outputs aren't guaranteed, because the hardware running the model can change results. Ch2 · Inconsistency

Hallucination

A response not grounded in facts. Two complementary hypotheses: Ch2 · Hallucination

  1. Self-delusion (DeepMind, 2021). The model can't tell the text it was given from the text it generated. After writing “Chip Huyen is an architect,” it treats that as fact and builds on it. Errors snowball.
  2. Knowledge mismatch (Leo Gao, John Schulman, OpenAI). In SFT the model imitates labelers' answers. When those answers use knowledge the model doesn't have, we're effectively teaching it to make things up.

Practical levers for now: ask for concise answers (fewer tokens means fewer chances to invent), tell it to say “I don't know,” and ground it with context (Chapters 5–6). Detecting hallucinations is covered in Chapter 4.
