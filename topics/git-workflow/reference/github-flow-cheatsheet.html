GitHub flow cheat sheet

The commands for one trip around the loop. Grows with each lesson: Lesson 1 · Lesson 2 · Lesson 3 · Lesson 4. Terms: glossary.

Model: a branch is a movable pointer to a commit. HEAD points to the branch you’re on. A commit moves only the branch HEAD points to. (Pro Git §3.1)

The loop

StepCommandWhat it does
0. Start freshgit switch main · git pullBranch from an up-to-date main
1. Branchgit switch -c <name>Create a label at the current commit and move HEAD to it
2. Commitgit add <files> · git commit -m "…"One self-contained change per commit
2. Push (first time)git push -u origin <name>Publish the branch and link it to origin/<name>
2. Push (later)git pushSend new commits to the linked remote branch
3. Open PRgh pr create --fillTitle and body come from your commits (--draft for early feedback)
3. Inspect PRgh pr view --webOpen the PR in the browser; read Files changed
4. Address reviewcommit · git pushThe PR updates itself
5–6. Merge & clean upgh pr merge --merge --delete-branchMerge on GitHub, delete the branch locally and remotely
7. Syncgit switch main · git pullBring the merge down to local main

Sync with GitHub

Model: there are three mains: GitHub’s, your bookmark origin/main, and your local main. git status compares the last two and never contacts GitHub. (Pro Git §3.5; Lesson 2)

Merge conflicts

<<<<<<< HEAD
your side (branch you're on)
=======
their side (branch you merged in)
>>>>>>> origin/main
StepCommand
Update branch from maingit fetch · git merge origin/main
What’s conflicted?git status (look for “both modified”)
Back out, nothing lostgit merge --abort
Resolveedit to the intended result, delete all 3 marker lines
No markers left?grep -nE '^(<{7}|={7}|>{7})' <file>
Mark resolved · finishgit add <file> · git commit --no-edit
Is the PR mergeable?gh pr view --json mergeable

Resolving isn’t picking a winner: check that both sides’ intent survived. Sources: Pro Git §3.2, git-merge. Lesson 3.

A green check proves only what the tests test, and the PR supplies both the tests and the workflow. Review changes to .github/workflows/ and the tests. Free plan: rulesets work on public repos only. Sources: GitHub Docs, rulesets, Actions quickstart. Lesson 5.

Merge methods on GitHub

Methodgh pr merge flagHistory result
Merge commit--mergeAll branch commits kept, plus a merge commit marking the join (always: GitHub merges with --no-ff)
Squash and merge--squashThe PR becomes one commit on main; individual commits are lost
Rebase and merge--rebaseCommits replayed onto main as new commits (new SHAs), with no merge commit

Source: GitHub Docs, “About merge methods on GitHub”. Flags: gh manual.

Agent rule of thumb

One task means one branch, and main moves only through a reviewed PR. That applies to agents too. (GitHub flow; Claude Code worktrees)
