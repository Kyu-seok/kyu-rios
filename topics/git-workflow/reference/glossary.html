Reference · Git workflow in the age of agents

Glossary

The course uses these words consistently. Grows with each lesson.

TermMeaningFrom
commitA saved snapshot of the project, identified by a hash such as f83f85a.L1
branchA movable pointer (label) to one commit. Committing moves the branch HEAD is on. It is not a copy of files.L1
HEADPointer to the branch you currently have checked out (* in git branch).L1
diffThe lines added (green) and removed (red) by a change. On GitHub it’s the PR’s Files changed tab.L1
pull request (PR)A request on GitHub to merge one branch into another, with discussion, review, and checks.L1
merge commitA commit with two parents that joins two lines of history.L1
GitHub flowBranch → commit → push → PR → review → merge → delete branch.L1
remote / originAnother copy of the repo that you sync with. origin is the default name, here your GitHub repo.L2
remote-tracking branchA bookmark such as origin/main: where a GitHub branch was the last time you talked to GitHub. It moves only on fetch, pull, or push.L2
upstreamThe remote-tracking branch a local branch is linked to (set by push -u). git status compares against it.L2
ahead / behindCommits your branch has that its upstream lacks, and the reverse.L2
divergedBoth ahead and behind: each side has commits the other lacks.L2
fast-forwardMoving a branch label forward along existing commits, with no merge commit. Only possible when you have no commits of your own.L2
pruneDelete remote-tracking branches whose GitHub branch no longer exists (git fetch --prune).L2
merge conflictBoth sides changed the same part of the same file (or one edited what the other deleted). Git marks it and waits for you.L3
conflict markers<<<<<<< HEAD (your side) · ======= · >>>>>>> name (their side). Delete them when you resolve.L3
resolveEdit the conflicted region into the intended result, then git add to mark it resolved.L3
abortgit merge --abort: return to the pre-merge state.L3
reviewLine comments plus one decision: Comment, Approve, or Request changes.L4
pending reviewLine comments you’ve drafted but not submitted. Only you can see them.L4
suggestionA line comment containing replacement code that the author can commit with one click.L4
scope creepChanges in a PR that don’t belong to its task, common in agent PRs.L4
workflowA YAML file in .github/workflows/ that GitHub Actions runs on events such as pull_request or push.L5
jobOne unit of work in a workflow, run on its own fresh machine (the runner). Each job appears on a PR as one check.L5
check (status check)A pass/fail result attached to a commit, shown on the PR as a tick or a cross.L5
required checkA check that must pass before a ruleset allows the PR to merge. You refer to it by the job’s name.L5
rulesetNamed rules on GitHub that apply to target branches, e.g. “require a PR” and “block force pushes” on main.L5
bypass listThe people or apps exempt from a ruleset. Empty by default, which includes admins.L5
