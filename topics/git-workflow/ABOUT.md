The GitHub workflow for someone who has used Git as a save-point tool on one branch: branches, remotes, pull requests, review, conflicts, checks and rulesets, with the extra twist of handing work to AI agents on their own branches. Practised in a throwaway repo with the `gh` CLI.

After this Topic you can:

- Take any change through the full flow: branch, commit, push, PR, review, checks, merge, sync
- Say where `main`, `origin/main` and `HEAD` point and what `fetch`, `pull` and `push` will do before running them
- Resolve a merge conflict and keep a branch current with `main` by merging or rebasing, knowing which fits
- Review a diff on GitHub as author and as reviewer: line comments, request changes, approve
- Give an AI agent its own branch or worktree, review its PR like a teammate's, and run several agents in parallel without collisions
- Set up CI checks, branch protection and rules that keep an agent off `main`
