Six Orchestration Shapes

From Anthropic's "Building effective agents." Pick the simplest one that works.

Workflow = you design the path in code. Agent = the model directs its own path. Graph = a workflow whose nodes may be agents. All are built from the augmented LLM (model + retrieval + tools + memory). [source]

ShapeWho decides pathUse when
① Prompt chainingYouSame fixed steps every time; add code gates between steps
② RoutingYou (classifier picks branch)Distinct input categories, reliably classifiable
③ ParallelizationYouIndependent parts (sectioning) or several attempts (voting)
④ Orchestrator-workersYou fix the shape; the orchestrator picks subtasksSubtasks only known at runtime
⑤ Evaluator-optimizerYouClear criteria; refining measurably helps (the evaluator may be tests)
⑥ Autonomous agentModelOpen-ended, unpredictable number of steps; needs a strong harness

Decision key: ask in order, stop at the first yes

  1. Model picks its own steps, unknown count? → Autonomous agent
  2. Work sent back to be redone? → Evaluator-optimizer
  3. Each input takes one branch of several? → Routing
  4. Simultaneous calls, list fixed by you in code? → Parallelization
  5. Simultaneous calls, list decided by a model after seeing input? → Orchestrator-workers
  6. Otherwise, fixed sequence (gates only stop, never send back) → Prompt chaining

Choosing, simplest first

  1. One call (+ retrieval, examples)
  2. Chaining / routing / parallelization
  3. + evaluator-optimizer if criteria are clear
  4. Orchestrator-workers if subtasks emerge at runtime
  5. Autonomous agent if steps are unpredictable
