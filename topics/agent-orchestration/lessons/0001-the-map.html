Lesson 1 · Agent Orchestration

The Map: Agent = Model + Harness

Before learning any single technique, learn where each buzzword sits.

Your win for this lesson

Given any agent technique, such as a CLAUDE.md file, a while loop or a team of reviewer agents, you can name its zoom level (prompt, context, harness, loop or graph) and the question that level answers.

1. What an agent actually is

Anthropic gives a precise definition: agents are "LLMs using tools based on environmental feedback in a loop."[1] That is all. The model picks a tool, the tool runs in the real world (read a file, run tests), the result comes back, and the model decides what to do next. It repeats until a stop condition is met: the task is done, a human is needed, or an iteration limit is hit.[1]

You already watch this every day in Claude Code. When you ask it to fix a bug, it greps, reads, edits and runs the tests. Each of those steps is one turn of the loop.

2. Agent = Model + Harness

The model is the engine. The harness is everything in an agent except the model itself: the system prompt, the tool definitions, what goes into the context, the tests it can run, the permission rules, the files it keeps notes in.[2] Birgitta Böckeler splits it in two:[2]

  • Inner harness is what the vendor ships. For Claude Code that is its system prompt, built-in tools, compaction and subagents.
  • Outer harness is what you add for your project, such as CLAUDE.md, linters, tests, hooks and CI.

This split matters for your career. You will rarely train models, but you will build outer harnesses all the time. OpenAI's team, who shipped roughly a million lines of agent-written code, summed up the new job as "Humans steer. Agents execute."[3]

3. Five zoom levels

The field keeps inventing new "X engineering" terms. Bouchard notes that "graph engineering" spread partly as a joke about how fast things get renamed.[4] Don't learn them as separate fads. Treat each one as a zoom level on the same system, and remember the question each level answers:

  1. Prompt engineering: What do I say in this one message?
    Scope: a single model call.
  2. Context engineering: Which tokens are in the window right now?
    The prompt, tool results, history, retrieved files. Context is a finite budget, and recall degrades as it fills ("context rot").[5]
  3. Harness engineering: What environment does the agent work in?
    Guides that steer it before it acts (CLAUDE.md, conventions) and sensors that check it after (tests, linters, review agents).[2]
  4. Loop engineering: How does one agent keep going until a verifier says done?
    One agent, one job, a real check, a hard stop.[4] The Ralph loop is its purest form: while :; do cat PROMPT.md | claude-code ; done.[6]
  5. Graph engineering: How do several loops connect?
    Explicit nodes (agents), handoffs, parallel branches and vetoes. "Graphs contain loops."[4]

Honest caveat

The levels overlap. A Ralph loop's PROMPT.md and plan file are also part of its harness. The ladder is a thinking tool, not a strict hierarchy. The useful habit is asking which question am I solving right now?

4. One task, five zoom levels

Take a task you might really give Claude Code: "add dark mode to my web app." Here is how each level would approach it:

LevelWhat you would do
PromptSay "use CSS variables" and show one example token in your request.
ContextLet it grep for just the theme files instead of pasting the whole repo, and keep its decisions in a notes file so they survive compaction.
HarnessCLAUDE.md says "colors live in tokens.css". A lint rule rejects hard-coded hex colors. A screenshot test renders both themes.
LoopA script reruns the agent until done. Each run takes the next unchecked screen from plan.md, fixes it, commits, and exits. It stops when the list is empty.
GraphOne agent per screen runs in parallel, a reviewer agent checks the screenshots, a fixer applies confirmed issues, and the tests decide whether to ship or loop back.

Notice the cost going up as you move down the table. Anthropic measured agents using about 4× the tokens of a chat, and multi-agent systems about 15×.[7] Their standing advice is to "consider adding complexity only when it demonstrably improves outcomes."[1] For dark mode, a good harness plus one agent is probably enough. Picking the right level is the core skill this course is building.

5. Practice: recall first

Scroll up so section 3 is out of sight. Then write the five zoom levels in order and the question each one answers. Struggling a little is the point: effortful recall builds memory that lasts.

  1. Prompt: what do I say in this one message?
  2. Context: which tokens are in the window right now?
  3. Harness: what environment does the agent work in (guides + sensors)?
  4. Loop: how does one agent keep going until a verifier says done?
  5. Graph: how do several loops connect?

Bonus: Agent = Model + Harness, and an agent is "LLMs using tools based on environmental feedback in a loop."

6. Practice: place the technique

For each technique, pick the zoom level it mainly works at.
