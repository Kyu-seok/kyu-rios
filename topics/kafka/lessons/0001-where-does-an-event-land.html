Where does an event land?

By the end, you can look at a key and a partition count and say what Kafka does and does not promise about order.

Most ordering questions come down to one thing: which partition an event went to. Four rules cover it.

The four rules

1. Order exists inside a partition, not across a topic. A consumer reads a partition's events in exactly the order they were written. A topic with several partitions has no overall order. Apache Kafka: Introduction
2. Same key, same partition, for as long as the partition count stays the same. The client computes toPositive(murmur2(keyBytes)) % numPartitions. The reverse isn't true: different keys can share a partition. Kafka source: BuiltInPartitioner
3. No key means sticky, not per-record round-robin. The default producer stays on one partition until about batch.size bytes have gone to it, then moves on. There is no per-key order to rely on. Apache Kafka: partitioner.class
4. Partitions can only grow, and growing remaps keys. Shrinking is not supported. After growing, a key may route to a different partition, and existing data does not move, so that key's old and new events can sit in different partitions. Apache Kafka: Basic Operations
Watch out: older material, including Confluent's Kafka 101, describes keyless events as round-robin. Current Apache docs describe sticky behaviour, and only the explicit RoundRobinPartitioner spreads consecutive records. Both descriptions agree that keyless events spread across partitions with no ordering guarantee.

Now on a real broker

Run this from the learn-kafka folder with Docker running. It starts its own throwaway broker and won't touch your other containers.

source assets/kafka-lab.sh
kafka_lab_up
k kafka-topics.sh --create --topic orders \
  --partitions 3 --replication-factor 1

printf 'alice:o1\nbob:o2\nalice:o3\ncarol:o4\nalice:o5\nbob:o6\n' | \
  k kafka-console-producer.sh --topic orders \
  --reader-property parse.key=true --reader-property key.separator=:

k_peek orders 3

Compare the output with the simulator. Next, try to shrink the topic, grow it, and send more events. Predict where alice lands first.

k kafka-topics.sh --alter --topic orders --partitions 2
k kafka-topics.sh --alter --topic orders --partitions 4

printf 'alice:o7\nbob:o8\ncarol:o9\n' | \
  k kafka-console-producer.sh --topic orders \
  --reader-property parse.key=true --reader-property key.separator=:

k_peek orders 4
kafka_lab_down

You should see the shrink fail with InvalidPartitionsException, and alice split across partitions 0 and 1. Each k_peek takes a few seconds per partition.
